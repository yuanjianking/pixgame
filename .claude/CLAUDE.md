# 西游 SRPG — 编码规范 & 设计哲学

## 技术栈
- Phaser 3 (Graphics API 纯代码绘图, 无贴图素材)
- TypeScript (strict mode)
- Vite 构建
- 纯前端, 无后端依赖

---

## 编码规则

### 类型安全
- ❌ **禁止使用 `any`** — 所有类型必须明确声明
- ✅ 使用 `interface` / `type` 定义数据结构, 导出复用
- ✅ 泛型约束优先于类型断言 (`as`)
- ✅ 外部数据 (存档、配置) 必须做防御读取 (`??` / `?.`)

### 代码风格
- **无注释原则**: 除非逻辑非直观 (隐藏约束、特定 workaround), 否则不写注释。标识符本身应表达意图
- **无遗留代码**: 不保留被删除代码的注释占位, 不重命名 `_unused` 变量
- **无过度抽象**: 三个相似行优于一个过早封装; 不为"将来可能"的场景做设计
- **无 emoji**: 不在代码或 UI 中使用 emoji

### 编译检查
- 每次代码创建/修改后必须运行 `npx tsc --noEmit` 确保无编译错误
- 禁止提交/推送有 TypeScript 编译错误的代码

## 美术规范 — Graphics API 纯代码渲染

### 总体要求：SRPG 商业级写实风格
角色和场景参考 `WuKong.ts` / `HuaguoshanScene.ts` 的渲染标准。

### 角色渲染标准
每个角色必须包含以下层次，缺一不可：
1. **身体分区** — 头、躯干、左臂、右臂、左腿、右腿（必要时加尾巴/披风/饰品）
2. **材质区分** — 至少 3 种材质：皮肤色（肉/毛）、金属色（盔甲/金饰）、布料色（衣服/披风）
3. **明暗层次** — 每个部件至少 2-3 层颜色（暗部/固有色/高光），用 `fillRect` 偏移模拟阴影
4. **轮廓光 (rim light)** — 身体一侧画半透明亮线，增加立体感
5. **动态表现** — 行走时身体上下弹跳、手臂/腿部摆动、尾巴晃动；攻击时手臂前伸 + 特效
6. **受击反馈** — `playHitFlash()` 红/白交替闪烁

### 场景渲染标准
1. **背景基调** — 渐变天空或纯色背景，不得留白
2. **地形纹理** — 地面要有细节（草地纹路、沙地波纹、石板缝、水中波纹）
3. **装饰元素** — 每个场景至少 2 种装饰类型（花/草/石/水/火把/家具等），15-20 个实例
4. **光影层次** — 环境光（半透明遮罩）+ 点光源（火把/洞口光）+ 动态光效（光柱摆动、水面闪烁）
5. **深度排序** — NPC / 障碍物 / 装饰 分层管理，角色在场景中正确前后遮挡

### 禁止
- ❌ 纯色平涂、单像素轮廓、无细节的几何堆砌
- ❌ 角色只有头+身体两段、没有肢体
- ❌ 场景只有纯色地面 + 方框障碍物

## 场景规范
- 每个场景继承 `Phaser.Scene`, 构造时用 `super({ key: 'SceneName' })`
- `init(data?)` 接收外部参数 (存档/胜利状态等), 必填参数用 `data?.` 防御
- `create()` 负责所有 UI 和对象创建
- `update()` 只做每帧逻辑 (移动/碰撞检测/场景切换)
- 场景切换使用 `cameras.main.fadeOut()` + `scene.start()` 带参数

### 场景架构模式（Map 分离）
每个场景按"三文件"组织：
1. `maps/<场景名>Map.ts` — 地图绘制 + 碰撞障碍物产出
   - 背景（渐变/纹理不得留纯色）
   - 建筑/地形/装饰
   - 动态特效（粒子/tween）
   - 导出 `obstacles[]` 给场景使用
2. `scenes/chapterN/<场景名>Scene.ts` — 场景逻辑编排
   - `init()` 接收入口坐标 + 存档数据
   - `create()` 调用 Map.render() → 创建玩家 → UI → 存档 → NPC → 输入 → 提示
   - `update()` 移动 + 出口检测
   - 不包含任何绘制方法
3. `scenes/index.ts` — 注册

参考实现：`HeavenMap.ts` + `TiantingScene.ts`。

### 入口位置优先级
`create()` 中设置玩家出生位置时，优先级顺序：
1. `this.entryPosition`（从 `init(data)` 传入的场景入口坐标）
2. `saved?.position`（存档中的玩家位置）
3. 硬编码默认值（场景的默认出生点）

```typescript
const startX = this.entryPosition?.x ?? saved?.position.x ?? 10 * TILE;
```

## 关键设计模式
- **SaveManager**: 单例, `updateSave(slot, mutator)` 模式用于修改存档
- **TaskManager**: 单例, 任务步骤驱动 (talk/arrive/kill), 通过 `markTalk`/`markArrive`/`completeTask` 推进
- **BaseCharacter**: 纯 Graphics 渲染, `draw(x,y)` + `updateAnimation()` 分离
- **碰撞**: `{ x, y, width, height }` 矩形碰撞, scene 维护 `obstacles[]`, 通过 `moveWithCollision()` 处理
- **DialogBox**: 打字机效果, 通过回调链实现多段对话, 按 J/Space/Enter 推进
- **HUD**: 每 1 秒刷新等级/任务信息

## 游戏设计哲学

### 核心定位
> "用代码绘制的西游题材 SRPG，在纯前端技术限制下达到商业级品质"

### 目标用户
- SRPG / 战棋类游戏玩家（Fire Emblem、梦幻模拟战、天地劫）
- 西游文化爱好者
- 网页游戏玩家（低门槛，打开即玩）

### 体验目标 (UX Pillars)
1. **"每一步都有反馈"** — 移动、对话、战斗、拾取，每个操作都有对应的视觉/文本反馈，不存在"点了没反应"
2. **"剧情有仪式感"** — 关键剧情节点用运镜（fade）、特效（光柱/粒子）、动画（弹入/缩放）来强化情绪
3. **"战斗有手感"** — 伤害浮动、暴击、飘字、震屏、闪光、粒子，让战棋有动作游戏的爽感
4. **"世界有沉浸感"** — 装饰细节、NPC 多样化对话、场景过渡渐隐渐现、任务有始有终

### "玩具 vs 产品" 分界线
以下特征决定一个项目是"玩具"还是"可商业化产品"：

| 维度 | 玩具 (Toy) | 产品 (Product) |
|------|-----------|---------------|
| 错误处理 | 没考虑，崩了就崩了 | 每个路径都有防御，失败有 fallback |
| 流程闭环 | 功能孤岛 | 开始→过程→结束有完整闭环 |
| 反馈密度 | 操作后可能无响应 | 每个操作都有反馈（音效/动画/文字） |
| 视觉层次 | 纯色平涂 | 多层渲染（暗部→固有色→高光→轮廓光） |
| 叙事 | 无 / 干巴巴的文字 | 有仪式感的对话 + 过场 + 演出 |
| 状态持久化 | 刷新就丢 | 存档/读档/进度追踪完整 |
| 引导 | 用户自己猜 | 操作提示 + 任务指引 + NPC 引导 |

## 商业化思路

### 游戏完整度标准（每个系统的最低完成线）

#### 场景
- [ ] 有渐变/纹理背景，非纯色
- [ ] 有至少 2 种装饰细节
- [ ] 有 NPC（至少 1 个，可对话）
- [ ] 有出口（回世界地图或下一场景）
- [ ] 场景切换有 fade 过渡
- [ ] 有操作提示（首次进入时显示）

#### 战斗
- [ ] 有完整回合制流程（玩家→敌人→玩家）
- [ ] 有移动范围高亮 + 攻击范围高亮
- [ ] 伤害有随机浮动（±20%）+ 暴击（10%）
- [ ] 有视觉反馈（飘字、震屏、受击闪烁、死亡效果）
- [ ] 敌人 AI 有基本策略（优先攻击低血量）
- [ ] 战后有结算面板（伤害统计、经验奖励）
- [ ] 战斗结果影响游戏世界（胜利/失败各有分支）

#### 剧情演出
- [ ] 对话有打字机效果
- [ ] 关键节点有特效/动画（不只有文字）
- [ ] 任务有接取→推进→完成→奖励的完整循环
- [ ] NPC 在任务前后的对话状态变化

#### 存档
- [ ] 自动存档（场景切换时）
- [ ] 玩家属性（等级/经验/装备/位置）正确持久化
- [ ] 任务进度正确持久化
- [ ] 读档后能恢复到正确场景和位置

### 内容规划（西游记章节路线图）

```
第 1 章：花果山 (已完成)
  ├── 场景：花果山 → 水帘洞 → 东海龙宫
  ├── 战斗：vs 虾兵蟹将 + 东海龙王
  └── 奖励：如意金箍棒

第 2 章：取经开端
  ├── 场景：鹰愁涧 → 观音禅院 → 高老庄
  ├── 队友：白龙马、猪八戒
  └── 战斗：vs 小白龙、黑熊精、猪八戒

第 3 章：流沙河 → 四圣试禅心 → 五庄观
  ├── 队友：沙和尚
  └── 战斗：vs 沙和尚、镇元大仙

第 4-10 章：八十一难逐步展开
  └── 每个章节 ≈ 2-3 场景 + 1-2 场战斗
```

每个章节应包含：
1. 剧情对话引入（Opening 或 in-game dialog）
2. 探索场景（与 NPC 交互、收集情报）
3. 战斗关卡（战棋战斗）
4. 胜利演出 + 奖励（武器/装备/新队友）
5. 回到世界地图，解锁下一节点

### 商业化制作的核心理念

**1. 闭环优先于内容量**
一个章节做完（剧情→探索→战斗→奖励→世界解锁），比做 5 个半成品章节更有价值。玩家感受到的是"完成了一个关卡"，而不是"玩了一个 demo"。

**2. 反馈密度决定品质感**
商业产品和玩具的核心区别不在技术复杂度，而在"每个操作都有回应"。打字机效果、伤害飘字、场景 fade、NPC 对话状态变化——这些单个看都很简单，叠加起来就是品质感。

**3. 用代码画图的取舍**
纯 Graphics API 的优势是不依赖素材管线，劣势是复杂视觉效果成本高。策略是：
- 角色：用多层矩形/椭圆叠加模拟像素画风，关键在颜色层次不在形状复杂
- 场景：用装饰实例数量取胜（20 朵花比 1 朵精致的花更有场景感）
- 特效：用 tweens + 简单几何形，效果够用即可

**4. 宁可少做，做完**
每个新功能必须满足"做完"的标准：有入口、有流程、有反馈、有出口、不出错。不积累半成品。

## 游戏背景设定

### 世界观
> 本游戏基于中国古典名著《西游记》改编，以孙悟空为主视角，从花果山称王到大闹天宫，再到护送唐僧西天取经，经历九九八十一难，最终修成正果。

### 时间线（当前实现范围）
```
石猴出世 → 花果山称王 → 水帘洞探秘 → 东海取兵器（当前节点）
   ↓
大闹天宫（后续）→ 五行山压五百年（后续）→ 取经团队集结（后续）
   ↓
八十一难（后续）→ 灵山取经（后续）
```

### 核心角色一览

| 角色 | 定位 | 加入时机 | 职业特色 |
|------|------|---------|---------|
| 孙悟空 | 主角 / 近战输出 | 初始 | 高攻高机动，金箍棒攻击范围随等级成长 |
| 白龙马 | 坐骑 / 辅助 | 鹰愁涧 | 高移速，载人移动，辅助 buff |
| 猪八戒 | 坦克 / 控制 | 高老庄 | 高血高防，控制技能，移动低 |
| 沙和尚 | 均衡 / 副输出 | 流沙河 | 攻守均衡，流沙地形优势 |

### 世界地图结构
世界地图以"东胜神洲→南赡部洲→西牛贺洲"为方向，从左到右、从上到下展开。当前实现到东海龙宫为止，后续节点已在地图上留位但未实现。

### 美术基调
- 配色：饱和度偏低的中国风配色（土黄/赭石/墨绿/朱红/藏青）
- 角色：写实比例的 Q 版（头身比 ≈ 1:3），保留西游人物的标志性特征（悟空的金箍+虎皮裙、八戒的猪头+钉耙）
- 场景：自然景观为主（山/水/洞/林），逐步加入城镇/寺庙/宫殿
- 氛围：偏暗色调的光影氛围（洞穴暗部 + 火把点缀、水下蓝色光柱、山顶雪光反照）
